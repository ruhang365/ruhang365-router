# 路由与交付策略

## 意图

| 意图 | 典型表达 | 默认公开能力 | 可选专项 Skill |
| --- | --- | --- | --- |
| `discover` | 不知道 AI 能做什么、找应用场景 | 知识、Skill 推荐 | 按最终场景决定 |
| `writing` | 文章、文案、脚本、改写、社媒发布 | 知识 | `ai-writing-humanizer` |
| `visual` | 封面、海报、信息图、生图、改图 | 知识、Prompt | `ruhang365-visual-prompt-router` |
| `tool` | 工具选择、软件比较、工作流选型 | 知识、Skill 推荐 | 按任务决定 |
| `knowledge` | 学习资料、教程、概念解释 | 知识 | 无 |

自动判断只作为离线后备。Agent 已经从上下文知道用户意图时，应显式传入 `--intent`。

## 专项 Skill 注册

专项 Skill 不在本文维护静态注册表。正式 ID、版本、用途、适用条件、许可证和仓库链接来自 Catalog 中的 `resource_kind=skill` 资产；专项代码继续留在独立仓库。不要把未审核候选或计划能力描述成已经可用。

## 交付合同

每次用户可见回复遵循同一个引导循环，但按对话自然表达，不强制机械标题：

1. **理解**：用一句话复述要完成的成果和最重要约束，让用户知道自己被正确理解。
2. **默认路线**：只给一个推荐，说明它为何适合当前时间、经验或资源；不把工具选择转嫁给用户。
3. **现在做**：当场提供一个首稿、填写块、3–10 分钟微任务或明确决策。不要只给链接、资料清单或未来步骤。
4. **进度与完成标志**：多轮任务用简短自然语言说明当前处于哪一阶段，以及完成这一阶段后会得到什么可检查结果。
5. **唯一下一步**：只要求用户做一个动作或回复一组紧密相关的事实；收到后直接继续交付。

当必要事实缺失时，一个紧凑填写块可以包含不超过 5 项与同一成果直接相关的字段；这仍算一个引导动作。说明缺失事实的用途，不询问不会改变当前产出的背景信息。

用户已经表示“不想选择”“别问太多”或“直接带我做”时，隐藏备选路线。用户主动要求比较时，才给 2–3 个选项，并明确默认推荐和差异。若两个候选会导致实质不同的成果且无法安全默认，可问一个会改变路线的问题。

推荐理由必须对应实际命中的身份、目标、经验、约束、交付物或任务词项。`recommendation_weight` 只能在已经相关的候选之间排序，不能让无关资产进入结果。

当用户不知道 AI 能做什么时，使用三层结构：

1. 选择 1 个与用户身份、目标和约束最匹配的已收录场景。
2. 把它缩成一个低风险、当天可完成的首个成果。
3. 直接产出首个草稿、填写块或执行清单。

只有用户明确要求比较时，才展示最多 3 个已收录候选；不足时如实返回。

## 连续引导与验收

- 用户没有改变目标或关键约束时，保持已经选择的路线，不在每轮重新诊断或重复候选列表。
- 复用对话里已经确认的事实。用户补充信息后立即完成下一段产出，不先复述整套方法。
- 对文章、Prompt、方案或清单，给出可观察的完成标准，例如事实已核对、必填字段齐全、可直接复制或用户已确认版本。
- 进入发布、发送或其他外部写操作前，先把成果标为待确认草稿，并让用户核对事实或指定一处修改；不要把“直接发布”当作首轮完成标志。收到明确的发布意图后再给发布步骤或执行获授权的操作，否则停在草稿或预览。
- 用户说“继续”时推进当前唯一下一步；不要回到入口重新让用户选择。

## 用户可见信息层级

默认先交付任务结果。不要在主回复中展示意图标签、匹配分数、Catalog 版本或摘要、API/缓存状态、字段命中、未调用能力清单等工程信息。

- 远程与离线结果一致且不影响推荐：不必打断用户。
- 降级导致覆盖变窄或证据缺失：在任务引导之后用一句话说明限制，并继续提供离线可完成路线。
- 用户询问来源、隐私、调用状态或为何推荐：再提供公开来源、推理边界和实际执行状态。

## 失败与降级

- 无匹配结果：扩大一个层级的场景词，最多重试一次。
- `401` 或 `403`：停止远程请求，不索取凭证，改用 Community 离线能力。
- `404`：标记服务版本不可用，不把旧 Preview 结果当作 Production。
- `429`：停止重试，保留离线路由。
- 超时或 `5xx`：最多重试一次；仍失败时明确降级。
- 专项 Skill 未安装：提供仓库链接和手工替代步骤，不自动改动用户环境。
