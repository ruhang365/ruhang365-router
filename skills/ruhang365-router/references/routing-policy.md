# 路由与交付策略

## 意图

| 意图 | 典型表达 | 默认公开能力 | 可选专项 Skill |
| --- | --- | --- | --- |
| `discover` | 不知道 AI 能做什么、找应用场景 | 知识、Skill 推荐 | 按最终场景决定 |
| `writing` | 文章、文案、脚本、改写、社媒发布 | 知识、Skill 推荐 | `ai-writing-humanizer` |
| `visual` | 封面、海报、信息图、生图、改图 | 知识、Skill 推荐、Prompt | `ruhang365-visual-prompt-router` |
| `tool` | 工具选择、软件比较、工作流选型 | 知识、Skill 推荐 | 按任务决定 |
| `knowledge` | 学习资料、教程、概念解释 | 知识 | 无 |

自动判断只作为离线后备。Agent 已经从上下文知道用户意图时，应显式传入 `--intent`。

## 专项 Skill 注册表

- 中文公开写作：`ai-writing-humanizer`
  - 仓库：https://github.com/ruhang365/ruhang365-ai-writing-humanizer-skill
  - 用途：诊断和去除模板化 AI 写作痕迹，同时保留事实、立场和作者声音。
- 场景出图：`ruhang365-visual-prompt-router`
  - 仓库：https://github.com/fzy2012/ruhang365-visual-prompt-skill
  - 用途：检索授权感知的视觉案例，生成任务专属 Prompt，再交给宿主图片工具执行。

注册表只声明已公开且可独立安装的项目。不要把计划中的能力描述成已经可用。

## 交付合同

最终回答至少包含：

1. 任务判断：用户要完成什么成果。
2. 推荐路线：为什么选择这些资料或专项 Skill。
3. 可直接使用的成果：正文、Prompt、步骤或决策建议。
4. 证据边界：哪些结果来自远程检索，哪些是本地推理。
5. 下一步：只保留一条最高价值行动。

当用户不知道 AI 能做什么时，使用三层结构：

1. 给出 3 个与用户身份和目标匹配的候选场景。
2. 推荐其中 1 个低风险、当天可完成的场景。
3. 直接产出首个草稿或执行清单。

## 失败与降级

- 无匹配结果：扩大一个层级的场景词，最多重试一次。
- `401` 或 `403`：停止远程请求，不索取凭证，改用 Community 离线能力。
- `404`：标记服务版本不可用，不把旧 Preview 结果当作 Production。
- `429`：停止重试，保留离线路由。
- 超时或 `5xx`：最多重试一次；仍失败时明确降级。
- 专项 Skill 未安装：提供仓库链接和手工替代步骤，不自动改动用户环境。
